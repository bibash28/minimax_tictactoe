## Overview

### Minimax Algorithm

Minimax is a foundational decision-making algorithm used in two-player zero-sum games. It works by recursively exploring all possible game states, alternating between a maximizing player (trying to achieve the highest score) and a minimizing player (trying to achieve the lowest score). While Minimax guarantees an optimal move, its exhaustive nature results in exponential time complexity O(b^d), where b is the branching factor and d is the search depth.

### Alpha-Beta Pruning

Alpha-Beta Pruning is an optimization of Minimax that eliminates redundant branches from the search tree without affecting the optimality of the solution. It maintains two values — alpha (best score the maximizer can guarantee) and beta (best score the minimizer can guarantee). When beta becomes less than or equal to alpha, the remaining branch is skipped (cutoff). In the best case, Alpha-Beta reduces the effective branching factor from b to b^(1/2), potentially doubling the searchable depth.

### Tic-Tac-Toe as Benchmark

Tic-Tac-Toe is a 3x3 grid game where two players alternate placing X and O. It is a perfect information, deterministic, zero-sum game with at most 9! = 362,880 possible move sequences. Its bounded state space makes it ideal for benchmarking — all results can be verified against known optimal play, and measurable performance differences appear between algorithms at varying depths.

## Study Design

Both algorithms are tested across:

- 3 search depths (1, 2, 3)
- 3 game stages (early, mid, late game)
- 21 board configurations → **63 benchmark runs**
- Each run repeated **5 times** — median value recorded

Performance is measured by **nodes explored**, **execution time (μs)**, and **pruning efficiency (%)**:

```
Pruning Efficiency (%) = [(Nodes_Minimax − Nodes_AlphaBeta) / Nodes_Minimax] × 100
```

---

## Key Findings

- Alpha-Beta Pruning achieved up to **61.22% node reduction** in early game at depth 2
- Both algorithms returned **identical moves across all 63 runs** — confirming Alpha-Beta does not sacrifice accuracy
- At depth 1, pruning efficiency is **0% across all stages** — tree too shallow for cutoffs
- Some mid and late game boards showed **0% pruning** due to worst-case move ordering

## Project Structure

```
lib/src/
  models/
    board.dart              — board representation, Cell, Player
    search_result.dart      — nodes explored, time, best move
    test_case.dart          — test case model with game stage
    benchmark_result.dart   — combined result for one benchmark run
  logic/
    board_evaluator.dart    — win detection and evaluation function
    minimax.dart            — Minimax algorithm implementation
    alphabeta.dart          — Alpha-Beta Pruning implementation
  runner/
    test_cases.dart         — all 21 board configurations
    benchmark_runner.dart   — runs all cases, computes median values
    csv_exporter.dart       — exports results to CSV

bin/
  minimax_tictactoe.dart    — entry point, prints results table

data/
  results.csv               — benchmark results (63 runs)
```

## Getting Started 🚀

**Requirements:** Dart SDK `^3.11.0`

Clone the repository:

```sh
git clone https://github.com/bibash28/minimax-tictactoe
cd minimax_tictactoe
dart pub get
```

---

## Running the Benchmark

```sh
dart run
```

This will:

1. Run all 21 board configurations at depths 1, 2, and 3
2. Execute each case 5 times and record the median
3. Print a full results table to console
4. Export results to `data/results.csv`
